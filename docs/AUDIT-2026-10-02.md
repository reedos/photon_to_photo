# Project audit — October 2, 2026

Scope: startup, the compact workspace, both bodies and all seven lenses, settings and sharing, part navigation,
optics/focus/pixel inspections, exposure and lesson playback, comparison experiments, real-photo predictions,
the Models viewer, and all five reference pages. Source review covered scenario/cache correctness, physical
parameter wiring, asynchronous lifecycle and recovery. Independent review reproduced the physics/cache and
inactive-loupe findings before the corrections.

## Findings and corrections

| Finding | Impact | Correction |
| --- | --- | --- |
| Changing body retained the previous body's sensor | Mirrorless could use D850 noise/readout values | Cross-body lens changes now select the new body's sensor unless that action explicitly supplies an override. |
| Subject distance was absent from the model cache key | A new subject distance could reuse the previous scene and motion values | Included subject distance; regression compares distinct rendered images and cache reuse. |
| Sensor cache omitted format; body dimensions ignored smaller formats | Format metadata depended on request order; cropping did not change the photo geometry | Cache includes format. Smaller formats on the D850/Z8 simulate centered crops with unchanged pitch/noise. Full-frame scan timing is explicitly retained. |
| Rounded sampling blocks extended outside the sensor crop | Preview field of view was too wide; loupe coordinates could be outside the active sensor | Continuous square sample spacing fits the requested image aspect inside the active sensor. Bayer noise averaging uses a separate integer block size; pixel coordinates include centered offsets. Actual 600×400 corner checks cover all three formats. |
| Rounded third-stop list omitted some exact maximum apertures | Slider and model dial could not return to the widest opening | Both controls use the same steps, starting at the prescription's exact maximum aperture. |
| Hyperfocal advice promised infinity sharpness unsupported by the lens's own DOF | Simplified pupil geometry could differ substantially from the correct sharpness boundary | Removed that KPI and replaced it with the explicit assumed blur criterion. Existing depth-of-field limits remain. The legacy internal hyperfocal field is annotated as a simplified approximation. |
| Shared links rounded exposure/distances and omitted overrides | Reloading or sharing could change the shot | Exact numeric serialization, sensor, shutter type, illumination and color temperature; legacy fractional shutter links still work. WebGL2 override and anchor survive updates. |
| Slow fractional-second labels rounded to the wrong reciprocal | 0.6 s appeared as 1/2 s and 0.8 s as 1/1 s | Show decimal durations when the reciprocal is not an integer; comparison captions use the same rule. |
| Unsupported color-temperature override could crash scene computation | A malformed shared shot could fail to load | Bounds temperature to the daylight model's 4000–25000 K range; rejects invalid illuminance and retains zero-light scenes. |
| Live render worker failure left an unusable worker and stuck progress | Changing settings could not reliably recover | Terminates failed worker, rejects pending work, creates a fresh worker on retry, clears busy state, offers a visible Retry photo action. |
| Renderer startup failure replaced the entire loading veil | Reload control was lost before it was wired | Wires Reload before renderer initialization; preserves actionable error UI. |
| A late loupe render could move the camera after leaving the loupe | The current view unexpectedly reframed | Only the active piece owns camera movement; hidden loupe render callbacks cannot schedule a dive. Re-entry refreshes its pixel from the latest render. |
| First animation timestamp could precede the Play click | Negative pipeline stage index crashed playback intermittently | Clamps elapsed time to nonnegative; browser regression deliberately offsets frame timestamps. |
| Models viewer accepted stale failed loads and offered no recovery | Earlier requests could overwrite newer state; failed loads required page reload | Load generations isolate success/failure and a retry control recovers the selected kit. |
| Models labels had insufficient contrast | Parts guidance and section labels were hard to read | Raised label contrast; automated accessibility checks cover the viewer and references. |
| Models kept desktop framing after resizing to portrait | Long lenses extended outside the phone view | Refit the model after the viewport aspect changes. |
| Aperture, shutter and ISO sliders exposed step indexes to assistive technology | Spoken values did not describe camera settings | Added actual photographic values through aria-valuetext. |
| Ray-color gate mixed color spaces and could accept dark background pixels | Unreliable evidence of correct displayed ray colors | Converts linear material color back to screenshot sRGB, freezes navigation motion during sampling, and requires visibly bright rays. The corrected gate matches a 493 nm ray exactly. |
| Bokeh canvas used linear values as sRGB colors | Spectral splats were too dark | Encodes colors for the canvas correctly. The shape gate isolates the production texture's alpha coverage from color brightness and grid annotations, retaining the existing aspect/scale tolerances and normal-color checks. |

## Validation

Final local run: **1,174 unit tests passed**, with the standalone render performance budget also passing.
TypeScript and production builds pass. All three optical accuracy gates pass. Browser checks passed at six
workspace sizes, four navigation/learning sizes, and desktop/phone animation and example views. Automated
accessibility checks reported zero violations on the workspace, lessons, comparison, Models and all five
reference pages. WebGL2, CPU throttling, zoom/reflow and injected-failure recovery checks passed.

`src/app/audit.test.ts`, `store.test.ts`, and `render-client.test.ts` cover scenario isolation, sensor crop/cache
semantics, aperture endpoints, exact sharing, illumination bounds, worker replacement, and stale-result handling.
`tools/test-audit.mjs` injects worker, asset-download and graphics-initialization failures; checks recovery and
exact links in a clean browser context; checks all reference pages at desktop/phone sizes; and checks Models
accessibility, stale loads, retries and phone overflow. Existing workspace, navigation, learning, animation,
examples, accessibility, compatibility and optical-accuracy gates supplement these regressions.

## Remaining validation and model limits

- Physical iPhone Safari, Android Chrome, an independent ordinary PC and screen-reader testing remain manual
  validation tasks. Emulated viewports and automated accessibility checks do not certify those experiences.
- Cropped modes retain full-frame scan timing. The fixed-aspect preview fits a centered window inside the active
  sensor; local Bayer block averaging approximates noise separately from continuous spatial sampling. These are
  not measurements of a camera's hardware crop mode.
- The unused legacy hyperfocal approximation still omits pupil offsets and focus-dependent geometry. It is no
  longer presented as a user instruction or sharpness guarantee.
- Synthetic scenes, reduced-resolution sampling, illustrative mechanical timing and representative material/
  transmission assumptions remain documented in Method. This audit does not claim new lab measurements or
  an exhaustive re-transcription of every patent surface.
