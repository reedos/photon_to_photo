# Workstream E2: closed-form optics and exposure

`src/engine/formats.ts`, `thinlens.ts`, `dof.ts`, `diffraction.ts`, `exposure.ts`. Pure TypeScript, no Three.js, no
DOM, no data imports (spectra and bins arrive as plain arrays from the caller). Every module's own file header and
function doc comments carry the full derivations and citations; this page is the map, the shared conventions, and
the list of known limits.

## Conventions

- Units follow `src/engine/types.ts`: lengths in mm, wavelengths in nm, time in s, angles in radians (callers
  convert to degrees for display - see the golden tests, which check degrees explicitly for readability).
- **Distance convention (thinlens.ts, dof.ts):** all object/image distances are the positive-distance photographic
  convention - object distance `u` from the front principal plane, positive in front of the lens; image distance
  `v` from the rear principal plane, positive behind it. The classic 1/f = 1/u + 1/v holds exactly in this
  convention for a thick lens too (that is what "principal plane" means), unlike the signed Cartesian convention
  `paraxial.ts` (E1b) uses internally.
- **Pupil magnification** (`pupilMag`, matching `Cardinal.pupilMag = xp.r / ep.r` in `types.ts`) shows up in two
  *different* places for two *different* physical reasons, and the two must not be conflated:
  - `exposure.ts`'s `workingFNumber(N, m, pupilMag)` = N(1 + |m|/p) is the bellows-extension exposure correction
    (depends on magnification m at the focus distance).
  - `dof.ts`'s `blurDiameter`/`hyperfocal`/`dofLimits` pupil correction models the defocus blur cone as being set
    by the *exit* pupil (diameter = pupilMag x entrance pupil diameter), independent of magnification.
  Both default to `pupilMag = 1` (thin lens / no correction) when omitted.
- **CoC and hyperfocal/DOF distances** (`dof.ts`) are measured from the front principal plane for the plain
  (`pupilMag = 1`) formulas; when pupil-magnification-correcting, the physically appropriate reference is the
  entrance pupil instead (see `dof.ts`'s module doc for why, and what this module doesn't have to make that exact).

## Module map

- **`formats.ts`** - FF/APS-C/MFT dimensions (with sources), diagonal, crop factor, `fov()` (with focus breathing
  via image distance), and equivalence (`equivalentFocalLength`/`equivalentFNumber`), derived from one requirement:
  hold the absolute entrance pupil diameter D = f/N constant. Equivalence is exact for the diagonal field of view
  (crop is diagonal-defined); for width/height alone it's only exact when both formats share an aspect ratio
  (FF's 3:2 and nominal APS-C's ~1.506:1 don't quite - see the module comment and `formats.test.ts`).
- **`thinlens.ts`** - the Gaussian conjugate equation, magnification, and `objectDistanceFromMechanical` (converts
  a tape-measure subject-to-sensor distance into a front-principal-plane object distance, given the principal
  planes' separation). Everything else in E2 that needs `imageDistance`/`objectDistance`/`magnification*` imports
  from here rather than reimplementing it, so a fix here propagates. `objectDistanceFromMechanical` returns `NaN`
  when the requested mechanical distance is inside the lens's minimum focus (total distance D < 4f - no real
  object/image conjugate exists there; see its doc comment for the derivation).
- **`dof.ts`** - `blurDiameter` (the one physical relation everything else in this module inverts), `hyperfocal`,
  `dofLimits` (near/far/total), `cocFor` (the assumed diag/1500 convention, divisor overridable). `blurDiameter`
  and `dofLimits` both accept `focus = Infinity` (the closed-form limit: sensor at v = f), matching
  `Scenario.focusM = null` ("focused at infinity") in `types.ts`.
- **`diffraction.ts`** - `j0`/`j1` (own implementation: power series below x=15, asymptotic expansion above;
  tested against an independent quadrature reference to <1e-6 absolute error, see `diffraction.test.ts`),
  `airyRadius`, `airyIntensity` (normalized so total encircled energy is 1), `encircledEnergy` (closed form
  1 - J0^2 - J1^2), `psfOnPixels` (2D Simpson integration with a Richardson-extrapolated error estimate),
  `mtfDiffraction`, and `diffractionLimitFNumber{,2px,1_5px}` (the Airy-diameter-equals-k-pixels criterion).
- **`exposure.ts`** - CODATA `PLANCK_H`/`SPEED_OF_LIGHT` (exact SI-defined values) and `photonEnergy`/`photonFlux`;
  `ev`/`ev100`/reciprocity; the ISO 2720 meter constant `METER_CONSTANT_K` (12.5, with `METER_CONSTANT_K_ALT` = 14
  cited as the common alternate); `workingFNumber` and the camera equation (`imageIlluminance`/`imageIrradiance`,
  with `effectiveSolidAngle` = pi/(4 N_w^2) derived from the paraxial image-side cone half-angle, not just quoted);
  `photonsPerPixelPerBin` (chains the camera equation, pixel area, exposure time and `photonEnergy` - no data
  imports, spectra are plain arrays via the shared `Bins` type); `tStop`; `motionBlurPixels`/
  `rollingShutterSkewPixels` (image-space speed = |magnification| x object speed, standard thin-lens scaling).

## Derivations worth knowing before you touch this code

- **Defocus blur** (`dof.ts`): a point at object distance p images at v_p = imageDistance(p, f); if the sensor
  actually sits at v_s = imageDistance(focus, f), similar triangles on the entrance-pupil cone give
  `blur = D * |v_p - v_s| / v_p`. `hyperfocal` and `dofLimits` both solve this same equation (for p = infinity, and
  for blur = c on each side of focus, respectively) rather than using independently-sourced shortcut formulas - so
  they're guaranteed mutually consistent, and (importantly) **not numerically identical** to the popular
  `H*s/(H+s-f)` "textbook shortcut" formula, which is an s>>f approximation. `dof.test.ts` cross-checks the two
  and documents the ~0.1-0.2% gap at s = 3f rather than asserting an equality that doesn't hold.
- **Airy intensity normalization** (`diffraction.ts`): rather than quoting a peak-intensity constant from a
  textbook, `airyIntensity`'s I0 = pi/(4(lambda N)^2) is derived from `encircledEnergy`'s closed form by
  differentiating EE(x) = 1 - J0(x)^2 - J1(x)^2 (using J0' = -J1, J1' = J0 - J1/x) to get dEE/dx = 2 J1(x)^2/x, and
  matching that to the `[2J1(x)/x]^2` intensity profile. This is why the two functions are guaranteed consistent
  with each other, and why the 83.8%-at-the-first-ring golden test constrains both at once.
- **The camera equation's solid angle** (`exposure.ts`): pi/(4 N_w^2) isn't just quoted - `effectiveSolidAngle`'s
  doc comment derives it from the image-side cone half-angle u' (sin u' ~ 1/(2 N_w) paraxially) via
  Omega = 2 pi(1 - cos u') ~ pi sin^2(u'), which is also where the "small angles" assumption in the camera
  equation's list of assumptions actually comes from.

## Known limits

- `j0`/`j1` are tested to <1e-6 absolute error over x in [0, 60] (measured ~5.8e-7 / ~3.0e-7); outside that range,
  or for higher precision, use a proper special-function library instead.
- `dof.ts`'s pupil-magnification correction and `exposure.ts`'s `workingFNumber` both use scalar `pupilMag` without
  the exit pupil's actual axial position (which only a traced system, from E1b's `paraxial.ts`, has) - fine as the
  standard engineering approximation, not exact for a real lens at macro distances.
- `psfOnPixels` models a pixel's photosensitive area as a centered square of side `pitch * sqrt(fill)`; real
  microlens/photodiode apertures aren't square. Labeled as an assumption in the function doc, not asserted as the
  true aperture shape.
- `diffractionLimitFNumber`'s k=2/k=1.5 variants are named engineering heuristics (Airy-diameter-equals-k-pixels),
  not a single rigorously-derived MTF threshold - there isn't one universally agreed name or number in the
  photography literature for "the" diffraction limit, so both are offered rather than picking one and calling it
  definitive.
- `formats.ts`'s APS-C dimensions are the commonly published nominal figures (23.5 x 15.6 mm Nikon/Sony/Fuji,
  22.3 x 14.9 mm Canon); real sensors vary by a few tenths of a mm between models within each family.
- No mechanical vignetting, no real lens aberrations, no spectral (V(lambda)-weighted) photometric conversion -
  `exposure.ts`'s `photometricFromRadiometric`/`radiometricFromPhotometric` are explicitly labeled as a 555 nm
  peak-sensitivity approximation, not spectrally accurate. All of that is later workstreams' (or E4's) job.
